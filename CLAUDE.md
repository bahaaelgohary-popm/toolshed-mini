# Toolshed Mini

## Project goal
A small web app: a catalog of AI skills, plugins and MCP connectors. People can search it and filter by kind and source (official or community). It must be simple enough to host for free as a live demo.

## Working rules
- The owner is a product manager, not a developer. Explain things in simple words.
- Always show a plan first and wait for the owner's OK before building.
- After building, run it and tell the owner which address to open in the browser.
- Keep the stack simple: plain HTML, CSS and JavaScript. No frameworks or databases unless the owner agrees.
- Use Node.js (installed) for scripts. Do not add dependencies without asking.
- Make small, easy-to-review changes. Commit to git when something works.

## How it works
- `catalog/` holds one `.md` file per item, in `key: value` lines: name, kind, description, owner, version, source, tags (comma-separated), updated (YYYY-MM-DD).
- `status` is `real` or `sample`. Real items are actual skills stored in `skills/<skill-name>/SKILL.md`, and need `path: skills/<skill-name>`. The checker makes sure that file exists, starts with a `---` header and that its `name` matches the folder. Only skills can be real for now. Sample items must not have a `path`.
- Real items show a "Get this skill" button with install steps (copy a command, new Claude Code session). The command links are built from the page's own address.
- `.nojekyll` must stay in the root: without it GitHub Pages turns `SKILL.md` files into HTML and the download breaks.
- The page shows items newest first (by `updated`), and search also matches tags.
- Allowed `kind`: skill, plugin, mcp-connector. Allowed `source`: official, community.
- `build-catalog.js` checks every item and packs them into `catalog.json` (generated by the script, never edited by hand). It is committed to git because free hosting serves it as-is. Run `npm run build` before each commit.
- `index.html`, `style.css`, `app.js` are the page. `serve.js` is a tiny local server.

## Commands
- `npm start` : rebuild the catalog and serve it at http://localhost:8000
- `npm run build` : rebuild `catalog.json` only (also runs the item checks)

## Roadmap (not built yet, do not build until asked)
1. **Publish flow:** a new item is submitted, checked automatically, then approved. Note: `build-catalog.js` already validates items, so reuse that check. Keep one file per item so a submission is just a new file.
2. **Usage event logging and impact dashboard:** record usage events (for example view, install) and show their impact on a dashboard. Keep item `id` stable (it is the file name) so events can refer to it.

Keep the structure simple, but do not make choices that block these two.
